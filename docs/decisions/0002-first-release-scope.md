# 0002: First-release simulation scope

- Status: Proposed (Developer 1 recommendation; needs team agreement)
- Date: 2026-11-14
- Deciders: team (Developers 1, 2, 3)

## Context

- The challenge brief encourages "two or three core resources, not five or six" (R10) and names "too many simultaneous systems for young players" as a pitfall. See [brief](../challenge/brief.md).
- [game-design.md](../design/game-design.md) (draft) caps core resources at three: power, oxygen, radiation.
- The RED FRONTIER plan (branch `docs/red-frontier-game-plan`, commit `7de7220`, marked "draft for team review") lists seven systems, eight facilities, 10 to 12 events and local save.
- Time: the Sofia listing puts the local demo deadline at Sun 15 Nov 14:00 and global submission at 23:59 ([SUBMISSION.md](../../SUBMISSION.md), to reconfirm onsite). At the time of writing roughly 24 hours remain to the local demo, including sleep, art, content, integration and a web build.
- No engine project exists in the repository yet.

## Options

1. **Full plan (seven systems).** Matches the draft. Not credible in the time left, and contradicts R10 and the named pitfall. Every extra system multiplies balancing, UI and content work for all three developers.
2. **game-design.md set: power, oxygen, radiation dose.** Smallest. Drops food, which the brief names as a decision area, and makes radiation a permanently visible meter although it only matters during storms.
3. **Three meters plus one outcome (recommended).** Power, Air, Food as stock resources. Crew Health as the single outcome meter. Radiation as an event-driven hazard that damages Crew Health unless the player pays to shelter.

## Decision (proposed)

Option 3.

| Element | First release | Notes |
|---|---|---|
| Power | Resource. Budget hub. | Generated by the solar array, stored in the battery, spent by facilities. |
| Air (life support) | Resource. | Water is folded in. Label it honestly as "life support (air and water)". |
| Food | Resource. | Greenhouse turns power into food. Second to be cut if time runs short (see below). |
| Crew Health | Outcome meter, 0 to 100. | Falls on shortages and radiation exposure, recovers slowly when all needs are met. Not spendable. |
| Radiation | Events only. | Choices trade power or lost work for protection. This is the NASA data hook (archived DONKI events). |
| Facilities | Solar array, habitat life support, greenhouse. | Each has an operating level (Off, Eco, Full). Storm shelter exists as an event choice, not a managed building. |
| Player actions | Set a facility's level, answer an event, advance the sol, restart. | |
| Mission | Survive a fixed number of sols (proposed 10) with Crew Health above zero. | Failure wording is Developer 3's; propose "crew evacuated", not death. |
| Events | 1 for the first slice, then 4 to 6 polished. | The draft's 10 to 12 is a stretch target. |

Cut from the first release, with consequence:

| Cut | Consequence |
|---|---|
| Water as its own resource | No recycling trade-off. One fewer meter for a 7-year-old to track. |
| Facility condition, repair, upgrades | Damage is expressed as timed output penalties from events. No workshop gameplay. |
| Morale / wellbeing | Crew recreation events can still exist as Health or Power trade-offs. |
| Communication delay | A brief-named theme is absent. Can appear as flavour in one event. |
| Local save / resume | A page refresh loses a 10-minute mission. Restart still works. State stays serialisable so save can be added later. |
| Conditional effects and flags | Consequences are immediate, timed or delayed, but do not branch on earlier choices. |

The simulation treats resources and facilities as data rows, so adding water or a fourth facility later is a configuration and balance change, not new system code. The choice of the third meter (Food versus a radiation meter) does not change the architecture in [0003](0003-simulation-architecture.md).

If time runs short, cut in this order: mission grade, random event pool (keep scripted events), forecast, Food and greenhouse.

## Consequences

- Easier: one screen of three meters and one health bar; balance by editing one file; content needs only three effect types.
- Harder: the draft's facility list shrinks, which changes Developer 2's map and Developer 3's event list. Both need to agree before building against it.
- Affects: simulation core (Developer 1), HUD and facility panels (Developer 2), event set and science notes (Developer 3).
- Revisit when: the team has a playable slice in a browser before Saturday night with time to spare; or a playtest with a child shows three meters are too few to create a real trade-off.
